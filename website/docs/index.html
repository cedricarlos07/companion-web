Qu'est-ce que Companion ?

Companion est la mémoire opérationnelle de votre entreprise, installée dans votre infrastructure. Il capture le savoir de vos équipes (documents, échanges, entretiens de transmission), l'organise en connaissances vérifiées et sourcées, mesure le risque de perte de savoir, assiste les transmissions de poste et accélère les onboardings — le tout accessible à vos collaborateurs et à vos agents IA, avec permissions et audit.

Les concepts en 60 secondes

ConceptRôle
Company BrainLe socle de connaissances validées de l'entreprise
Employee MemoryCe que chaque collaborateur sait — avec provenance
Role BrainLe savoir du poste, validé et transmissible
Knowledge RiskLe score de risque de perte de savoir
HandoverLe dossier de transmission de poste
OnboardingLe plan J1 / J7 / J30 du nouvel arrivant
Companion est self-hosted : vos données restent chez vous. Seule la licence est fournie par KamaLoka.

Installer Companion en 10 minutes

Une machine, quatre commandes. Tout le reste est automatisé.

1. Pré-requis

ÉlémentMinimum
ServeurUbuntu 24.04+ (VPS, cloud privé ou interne)
CPU / RAM4 CPU · 8 Go RAM
Disque50 Go SSD
LogicielDocker + Docker Compose v2
RéseauUn nom de domaine pointant vers le serveur

2. Installation

Récupérez le kit d'installation depuis votre portail client, puis :

unzip companion-kit.zip && cd companion-kit
sudo ./install.sh

Le script vérifie les pré-requis, génère vos secrets, démarre la stack complète (base de données, cache, intégrations, application) et enregistre votre licence.

La licence companion-license.lic reçue de KamaLoka peut être passée au script (COMPANION_LICENSE_FILE=… ./install.sh) ou collée à la demande.

3. Ouvrir

https://companion.votreentreprise.com

4. Importer votre licence

Connectez-vous avec le compte administrateur créé à l'installation, puis Paramètres → Facturation → Importer une licence : collez le contenu du fichier .lic. Votre plan est activé immédiatement, hors-ligne.

5. Créer l'organisation

L'assistant de premier démarrage vous demande le nom de l'entreprise, le secteur, le compte administrateur, et invite vos premiers collaborateurs.

6. Connecter Google Drive / Microsoft 365

Sources → Connecter : choisissez votre espace, autorisez l'accès OAuth — l'ingestion démarre aussitôt (extraction, découpage, indexation, tout est sourcé).

Terminé. Posez votre première question dans « Ask Companion » avec la citation de sa source.

Premier démarrage

Après l'installation, l'assistant /setup crée votre organisation en 5 étapes :

  1. Organisation — nom, secteur, pays, taille, langue, compte administrateur.
  2. Intelligence — modèle d'analyse local (par défaut, aucune donnée n'en sort) ou fournisseur externe avec votre clé API.
  3. Sources — fichiers locaux, Drive, Gmail, Microsoft 365, Notion, Slack…
  4. Équipe — invitations des collaborateurs (elles partent par email avec un lien d'activation).
  5. Terminé — session ouverte directement.

Les 3 premières actions recommandées

  1. Importez 5 à 10 documents représentatifs (procédures, comptes-rendus) dans Sources.
  2. Posez une question métier dans Ask Companion et vérifiez la citation de la source.
  3. Ouvrez Knowledge Risk : le score initial de votre organisation est calculé.

Connecter votre première source

  1. Sources → Nouvelle source.
  2. Choisissez Fichiers locaux pour démarrer (PDF, DOCX, TXT, MD, CSV) — glissez-déposez vos documents.
  3. Laissez l'ingestion se terminer : extraction → normalisation → découpage → indexation. Chaque fragment garde sa source.

Qualité d'ingestion : ce qu'il faut savoir

  • Les documents importés produisent des candidats : ils deviennent « validés » après relecture humaine.
  • Le doublon détecté n'est pas créé deux fois ; une contradiction est signalée plutôt qu'écrasée.
  • Les sources connectées (Drive, Gmail…) s'ingèrent en continu, sans intervention.
Astuce : commencez petit — 10 documents qui font vraiment autorité valent mieux que 1 000 documents en vrac.

Company Brain

Le Company Brain est le socle de connaissances partagées de l'entreprise : procédures, décisions, faits métier. Chaque connaissance y porte sa provenance (document d'origine, auteur), son statut (candidat, validé, contesté, obsolète) et son historique de versions.

Statuts de connaissance

StatutSignification
candidateDétectée ou importée, en attente de validation humaine
verifiedValidée par un porteur du savoir — citée avec confiance « Validé »
contestedContradiction signalée — à arbitrer
deprecatedObsolète, conservée pour l'historique

Les candidats ne deviennent jamais « validées » automatiquement : une main humaine tranche. C'est ce qui rend les réponses de Companion fiables.

Employee Memory

Chaque collaborateur dispose d'une mémoire individuelle : ce qu'il sait, ce qu'il a fait, ce qu'il a documenté. Elle s'enrichit de trois façons :

  • Documents — ce qu'il écrit (procédures, comptes-rendus) est rattaché à sa mémoire ;
  • Entretiens de transmission — les réponses aux questions de handover deviennent des candidats de sa mémoire ;
  • Corrections — toute correction apportée à une réponse est capturée, pas perdue.
La mémoire d'un employé n'est visible que selon les permissions de chacun — voir Permissions.

Role Brain

Le Role Brain contient le savoir du poste, pas de la personne : les procédures et connaissances qu'un titulaire du rôle doit maîtriser, validées et structurées.

Pourquoi c'est central

  • Un handover s'appuie sur le Role Brain pour mesurer ce qui manque ;
  • Un onboarding est construit depuis le Role Brain du poste d'arrivée ;
  • Les agents s'appuient sur le contexte du rôle pour agir correctement.

Alimenter un Role Brain

Depuis une connaissance validée de la mémoire d'un employé : Promouvoir vers un rôle. La connaissance reste chez l'individu (avec sa provenance) et une copie validée rejoint le rôle.

Ask Companion

Posez votre question en français naturel. Companion cherche dans la mémoire (moteur hybride), applique vos permissions, puis répond avec citations : document source, propriétaire, niveau de validation.

Les engagements

  • Citation systématique — chaque affirmation pointe vers sa source ;
  • Abstention honnête — si le contexte ne suffit pas, Companion dit « je ne sais pas » plutôt que d'inventer ;
  • Filtres — restreindre à un rôle, un département, un employé ou un type de connaissance ;
  • Moteurs — hybride (défaut), natif ou Mem0, comparables à tout instant.

Questions bien posées

« Comment traite-t-on un rejet R03 supérieur à 500 000 FCFA ? »
« Quelles sont les étapes de validation d'un appel d'offres ? »
« Quelle est la procédure d'escalade fournisseur du poste de comptable ? »

Knowledge Risk

Un score global (0–100) et cinq facteurs détaillés qui mesurent le risque que votre entreprise perde du savoir :

FacteurQuestion posée
Dépendance aux personnes clésQuel savoir n'existe que dans une seule tête ?
Couverture des rôlesQuels postes n'ont pas de savoir validé ?
FraîcheurQuand les connaissances clés ont-elles été confirmées ?
Diversité des sourcesLe savoir repose-t-il sur plusieurs canaux ?
Préparation des handoversLes transmissions sont-elles prêtes ?

Chaque facteur pointe vers les employés, rôles et documents concernés : le score devient un plan d'action, pas juste un chiffre. Le suivi dans le temps se fait via l'API et le journal d'audit.

Handover — transmission de poste

Le flux

  1. Analyser — Companion compare la mémoire de l'employé partant au Role Brain de son poste ;
  2. Détecter les manques — ce que lui seul sait apparaît explicitement ;
  3. Questionner — un entretien ciblé lui pose les questions qui comblent les manques ;
  4. Valider — chaque réponse devient une connaissance candidate, relue puis validée ;
  5. Transmettre — le pack de handover est généré : version humaine lisible + version machine pour les agents.

Successeur & readiness

Désignez un successeur : son onboarding peut être généré automatiquement depuis le handover, avec un score de préparation (readiness) qui progresse à mesure que les manques sont comblés.

Un handover se lance idéalement 3 à 6 semaines avant le départ — assez tôt pour l'entretien, assez tard pour que le savoir soit à jour.

Onboarding

Générez un plan d'arrivée structuré en trois phases :

PhaseContenu

J7Ce qu'il faut maîtriser la première semaine : processus du poste, cas particuliers

Comprendre les agents

Companion embarque quatre agents spécialisés, alimentés par la même mémoire et soumis aux mêmes permissions :

AgentMission
Knowledge AgentDétecte les contradictions, propose des corrections sourcées
Handover CopilotAnalyse les manques, prépare les entretiens et les packs
Onboarding CopilotConstruit les plans J1 / J7 / J30
Company AssistantRépond aux questions avec citations, prépare les brouillons

Chaque exécution (run) est persistée : plan suivi, étapes, outils appelés, décisions de politique, tokens consommés, coût estimé, score de vérification. Rien n'est une boîte noire.

Agents

Approvals

Avant toute action sensible (envoi d'email, écriture externe), l'agent suspend son travail et soumet une demande d'approbation : action prévue, aperçu du contenu, sources utilisées, raison.

  • Approuver → le workflow reprend exactement où il s'était arrêté ;
  • Rejeter → le run se termine proprement, avec l'état « rejeté » journalisé ;
  • Les décisions sont attribuées (qui, quand) et conservées dans l'audit.

Les demandes en attente apparaissent dans Approvals et dans la cloche de notifications.

Activity / Audit

Activity montre l'activité des agents (runs, étapes, outils). Le journal d'audit — plus large — enregistre toutes les actions sensibles de la plateforme :

Permissions

Les permissions s'appliquent jusqu'au retrieval : une question posée par un employé ne peut pas faire remonter une connaissance hors de son périmètre, même par détours (citations, agents, MCP).

  • Portée par département et par poste ;
  • Les agents héritent des permissions de leur initiateur et de leur périmètre d'agent ;
  • Tentative d'accès hors périmètre = refus explicite, journalisé (DENIED).

Licences

Votre licence est un fichier signé cryptographiquement (Ed25519) par KamaLoka : aucune connexion n'est nécessaire pour la vérifier.

Installer / renouveler

  1. Paramètres → Facturation → Importer une licence ;
  2. Collez le contenu du fichier companion-license.lic reçu du portail client ;
  3. Le plan correspondant s'active immédiatement (limites, fonctionnalités).

Cycle de vie

ÉtatEffet
ActiveTout fonctionne
Grâce (30 j après expiration)Tout fonctionne + rappel de renouvellement
RestreintConsultation, export et backups restent libres ; créations (utilisateurs, agents, intégrations, actions agentiques) suspendues
Vos données ne sont jamais prises en otage : même sans licence, tout est accessible et exportable.

Mises à jour

Companion vérifie périodiquement la dernière version stable publiée par KamaLoka et l'affiche dans les paramètres. Aucune mise à jour n'est jamais appliquée automatiquement.

Procédure recommandée

1. Sauvegarde complète        →  POST /api/backup
2. Récupérer le nouveau kit   →  portail client
3. docker compose pull && docker compose up -d
4. Vérifier la santé          →  /api/status (IA OK, mémoire OK)
5. En cas de problème         →  restaurer la sauvegarde + image précédente

  • Chiffrement — secrets et identifiants d'intégration chiffrés au repos (AES-256-GCM) ;

MCP Server

Companion expose un serveur MCP (Model Context Protocol) : vos assistants et agents externes (Claude, Cursor, agents maison) interrogent la mémoire d'entreprise — avec permissions, scopes et audit.

Endpoint

POST https://companion.votreentreprise.com/mcp
Authorization: Bearer <token client MCP>

Outils exposés

OutilDescription
search_memoryRecherche sourcée dans la mémoire autorisée
get_company_contextContexte général de l'entreprise
get_role_context / get_employee_contextContexte d'un poste ou d'une personne
get_project_contextContexte d'un projet
get_knowledge_gapsManques de savoir détectés
create_memoryCréer une candidature de connaissance (jamais validée d'office)
correct_memoryProposer une correction sourcée
create_handover / request_approvalLancer une transmission, demander une approbation

Les clients MCP sont créés par un admin (scopes, outils autorisés, expiration) et révocables à tout moment. Toute demande hors périmètre reçoit DENIED et est journalisée.

Dépannage

Mem0 degraded

Symptôme : l'état mémoire affiche « dégradé » ou le moteur retombe sur le moteur natif.

  • Vérifiez que le modèle local tourne : curl http://127.0.0.1:11434/api/tags ;
  • Modèles requis présents (ollama pull qwen2.5:7b nomic-embed-text) ;
  • Le mode dégradé n'interrompt pas le service : Companion bascule sur le moteur natif et continue de répondre.
← DiagnosticSuivant · Activepieces offline →
Dépannage

Activepieces offline

Symptôme : les connexions Drive/Gmail ne se créent plus ou les outils externes disparaissent.

  • docker compose ps activepieces — le conteneur doit être « Up » ;
  • Redémarrage : docker compose restart activepieces ;
  • Companion redécouvre les outils automatiquement au retour du service — rien à reconfigurer.
